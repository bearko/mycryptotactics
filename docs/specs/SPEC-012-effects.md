## 1. 概要

DESIGN_CHARTER 1.1（2.4）で、条件つきで軽い演出が許された。戦闘と画面の切り替えに、手ごたえを足す。**すべて 0.8 秒以内・操作を止めない・reduced-motion と「演出を減らす」で止まる（止めても情報は失われない）**。

## 2. 背景と動機

いまの即時フィードバック（DESIGN_CHARTER 1.3）は、ヒットフラッシュ・突進・数値ポップ・SE。足りないところ：

- 敵を倒した瞬間が、HP バーが 0 になるだけで分かりにくい
- 味方が被弾したとき、ポートレートが光るだけで、画面の中で気づきにくい（特に 3v3 の後衛）
- ゴールド（GUM）は数字が一瞬で書き換わり、増えた・減ったの実感がない
- 画面（マップ・戦闘・ショップ・報酬など）がパッと切り替わり、どこに来たかが分かりにくい

## 3. 目標と非目標

### 目標

| 場面 | 演出 | 長さ |
|---|---|---|
| 敵を倒す | 敵のポートレートから粒が散る（12 粒、敵の色＋白） | 0.6 秒 |
| 味方が被弾 | 画面の縁が赤く光る（ダメージが大きいほど濃く） | 0.35 秒 |
| ゴールドが変わる | 数字を前の値から数え上げる。増えたら金色、減ったら赤く一瞬光る | 0.5 秒 |
| 画面が切り替わる | 入ってくる画面が下から少し上がりつつ現れる | 0.22 秒 |

- 演出の要素は `pointer-events: none`。演出の間も操作できる（待ち時間を足さない）
- `prefersReducedMotion()`（SPEC-011：OS の設定か「演出を減らす」）が true なら、粒・縁の光・切り替えの動きは出さない。ゴールドはすぐ最後の値にする
- 粒は同時に 60 個まで

### 非目標

- 長いカットイン・画面全体の揺れ（DESIGN_CHARTER 6 のまま）
- 新しい音（SE は今のまま）
- 戦闘の数式・テンポ（ターンの待ち時間）の変更

## 4. スコープ

| ファイル | 変更 |
|---|---|
| `prototype/js/fx.js`（新規） | `burstAt(el, color)`・`hurtEdge(strength)`・`countTo(el, to)`・`enterView(el)`、純関数 `countValueAt(from, to, t, dur)`・`easeOutCubic` |
| `prototype/js/main.js` | `applyHpDeltaToEnemy`（生→死で `burstAt`）、`applyHpDeltaToHero`（減ったら `hurtEdge`）、`syncResources`（ゴールドを `countTo`）、`showView`（`enterView`） |
| `prototype/index.html` | 縁の光の要素、粒・縁・ゴールドの光・画面の切り替えの CSS |

## 5. 受け入れ基準

- [x] 敵を倒すと粒が散り、0.6 秒で消える。同時に 60 個を超えない
- [x] 味方の HP が減ると画面の縁が赤く光る
- [x] ゴールドが前の値から数え上がる（増減で色）
- [x] 画面が切り替わるときに動きがつく
- [x] 演出の間もカード・ボタンを押せる
- [x] 「演出を減らす」・reduced-motion で、粒・縁・動きが出ず、ゴールドはすぐ最後の値
- [x] `node --test tests/*.test.mjs` が通る（`countValueAt` のテストを足す）

## 6. テスト

- `tests/fx.test.mjs`：`easeOutCubic`・`countValueAt`（始まり・途中・終わり・減るとき）
- 手動（Playwright）：敵を倒す・被弾・ゴールドの変化・画面の切り替えを撮る。「演出を減らす」で出ないこと
