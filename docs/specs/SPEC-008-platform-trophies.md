## 1. 概要

bearko.games の共通基盤（[bearko/mycryptoportfolio の SPEC-001](https://github.com/bearko/mycryptoportfolio/blob/claude/game-portfolio-page-4afqbc/docs/specs/SPEC-001-bearko-games-platform.md)）のトロフィー機能に、本作から参加する。章をクリアしたときに、共通基盤の SDK を通してトロフィーを送る。

## 2. 背景と動機

- bearko.games 配下の全タイトルで、共通ログイン・タイトル横断のトロフィー・総合スコア・RTA を始める（作者の決定 2026-10-15）
- PROJECT_CHARTER 3.0 で、共通基盤との連携をスコープに入れた（ログインなしで最後まで遊べることは守る）
- 共通基盤の段階 2（トロフィー）が bearko.games に公開済み（SDK 1.1.0）

## 3. 目標と非目標

### 目標（Goals）

- 章クリア・全章クリアで、共通基盤のトロフィーを獲得できる
- ログインしていなくても獲得でき、あとでログインしたときにまとめて登録される（共通基盤の仮アカウント）

### 非目標（Non-goals）

- 総合スコア・RTA への参加（共通基盤の段階 3・4 で別の SPEC にする）
- 既存の GAS ランキング（SPEC-007）の置き換え
- 本作のコードでの Cookie・localStorage の利用（ログイン状態は共通基盤が持つ）

## 4. スコープ

### 含む

- `prototype/index.html` で共通基盤の SDK（`https://bearko.games/sdk/v1.js`）を読み込む
- `prototype/js/platform.js`（新規）：SDK を呼ぶ薄い窓口。SDK がなくても何もしないで終わる
- 章クリアの処理（`main.js` の `advanceToNextChapter`）から、トロフィーを送る

### 含まない

- ログインボタンなどの UI の追加（獲得時の通知とログインの案内は SDK が出す）
- トロフィーの定義の変更（定義は共通基盤の `platform/trophies.js` にある）

## 5. 契約と挙動

### 入力

章クリア時（`advanceToNextChapter` で `clearedChapters.add` した直後）の、クリアした章の番号（0 始まり）と、それが最終章かどうか。

### 出力・副作用

| クリアした章 | 送るトロフィー |
|---|---|
| 第 1 章（`chapterIdx` 0） | `tactics.ch1` |
| 第 2 章（`chapterIdx` 1） | `tactics.ch2` |
| 最終章（第 5 章） | `tactics.clear` |
| 第 3・4 章 | なし |

- どのレギュレーションでクリアしても同じトロフィーを送る
- 通知は SDK が画面下に出す（未ログインなら「未登録のトロフィー n 個 — ログインして登録」を添える）

### エラー条件

- SDK が読み込めない・通信に失敗した場合は、何もしない（ゲームの進行を止めない・例外を出さない）。失敗は `console.warn` に出すだけ

### 互換性

- SDK は `defer` で読み込み、`main.js`（module）より先に並べる。SDK がないとき（ローカルで開いたときなど）も、ゲームはそのまま動く
- 依存の追加はない（SDK は作者管理の自前スクリプト。DEVELOPMENT_CHARTER 2.3 の例外）

## 6. 非機能要件

- 通信は章クリア時の 1 回だけ（ゲーム中の負荷は増えない）

## 7. Human-in-the-loop

- トロフィーの名前・条件は、共通基盤の SPEC-001 9.4 で作者が見直す（ID は変えない）

## 8. 受け入れ基準

- [ ] 第 1 章をクリアすると「兵は詭道なり」の通知が出る
- [ ] 全章クリアで「天下布武」の通知が出る
- [ ] 未ログインで獲得したトロフィーが、`https://bearko.games/me/` に「未登録」として出て、ログインすると登録される
- [ ] SDK が読めない状態（オフラインなど）でも、章を進めて全章クリアまで遊べる

## 9. テストと証跡

- `prototype/js/platform.js` の「章 → トロフィー ID」の対応を、Node 標準 `assert` でテストする
- 手動 QA：上の受け入れ基準を PR 本文のチェックリストで確認する
